== Etag (Entity Tag)

=== 定义
* Etag（实体标签）是 HTTP 协议中用于缓存验证的机制之一
* 它是由服务器端生成的一串唯一标识符, 通常是文件内容或其某些属性（如修改时间、大小等）的哈希值
* 当资源内容发生变化时, 服务器会生成一个新的 Etag
* 浏览器（通常是浏览器）在第一次请求资源时会获取到这个 Etag, 并在后续请求中将其发送回服务器, 以便服务器判断资源是否已更新

=== 工作原理
.  首次请求资源
    - 浏览器向服务器发起对某个资源的请求
    - 服务器处理请求, 并计算该资源的 Etag 值, 将其放入 `ETag` 响应头中, 连同资源内容一同返回给浏览器
    - 浏览器接收到响应后, 会将资源内容和 Etag 值一并缓存起来

. 后续请求资源（缓存验证）
    -   当浏览器再次请求同一个资源时, 它会从本地缓存中取出上次获取到的 Etag 值, 并将其放入 `If-None-Match` 请求头中, 发送给服务器
    -   服务器接收到带有 `If-None-Match` 头的请求后, 会执行以下操作：
        -   计算当前资源的 Etag 值
        -   将计算出的 Etag 值与浏览器发送的 `If-None-Match` 值进行比较
        -   **如果两者匹配：** 说明资源未发生变化。服务器返回一个 `304 Not Modified` 状态码, 响应体为空, 不包含资源内容。
        -   **如果两者不匹配：** 说明资源已发生变化。服务器会像首次请求一样, 返回 `200 OK` 状态码, 并包含最新的资源内容和新的 `ETag` 响应头。
    -   浏览器接收到 `304 Not Modified` 响应后, 会从本地缓存中读取资源并使用, 从而避免了重新下载整个资源, 节省了带宽和加载时间。如果接收到 `200 OK` 响应, 则更新本地缓存。

== Cache-Control

=== 定义
* `Cache-Control` 是 HTTP/1.1 中最重要的缓存控制头, 用于控制所有缓存机制在缓存请求/响应时的行为
* 它是一个通用头, 可以出现在请求头和响应头中
* 通过一系列指令, 它详细规定了浏览器、代理服务器和服务器之间的缓存策略

=== 指令
* `Cache-Control` 头可以包含多个指令, 每个指令用逗号分隔

**常见响应指令：**

-   **`public`**：表明响应可以被任何缓存（包括共享缓存, 如代理服务器）缓存
-   **`private`**：表明响应只能被私有缓存（如浏览器缓存）缓存, 不能被共享缓存缓存
-   **`no-cache`**：强制所有缓存（无论是私有还是共享）在使用已缓存的响应之前, 必须先将请求提交到源服务器进行验证。这意味着每次请求都会发送一个验证请求（如带有 `If-None-Match` 或 `If-Modified-Since`）
-   **`no-store`**：禁止缓存对响应的任何存储。这意味着每次用户请求都会从服务器下载完整的响应
-   **`max-age=<seconds>`**：设置缓存的有效期, 单位为秒。在这个有效期内, 缓存可以直接使用本地副本, 无需向服务器验证
-   **`s-maxage=<seconds>`**：与 `max-age` 类似, 但只适用于共享缓存（代理服务器）。私有缓存会忽略此指令
-   **`must-revalidate`**：当缓存过期时（超过 `max-age` 或 `Expires`）, 必须向源服务器验证缓存的有效性。如果源服务器不可用, 缓存不能使用过期资
-   **`proxy-revalidate`**：与 `must-revalidate` 类似, 但只适用于共享缓存
-   **`immutable`**：表示响应内容不会随时间改变。一旦被缓存, 除非缓存到期或手动被清除, 否则缓存将永远使用这个副本, 而不会进行重新验证。主要用于 CDN 上的静态资源

**常见请求指令：**

-   **`no-cache`**：浏览器希望缓存不直接提供旧的缓存, 而是向源服务器验证
-   **`no-store`**：浏览器不希望任何缓存存储此请求的响应
-   **`max-age=<seconds>`**：浏览器只接受存在时间不大于指定秒数的缓存响应
-   **`max-stale[=<seconds>]`**：浏览器愿意接受一个过期的响应。如果指定了秒数, 则表示愿意接受过期时间在指定秒数之内的响应
-   **`min-fresh=<seconds>`**：浏览器希望响应的缓存时间至少还有指定秒数
-   **`only-if-cached`**：浏览器只接受缓存响应, 如果缓存中没有, 则返回 `504 Gateway Timeout` 状态码

=== 工作原理

`Cache-Control` 通过其指令集, 指导浏览器（浏览器）和中间缓存（代理服务器、CDN）如何存储、使用和验证缓存的资源。

. **设置有效期：** `max-age` 和 `s-maxage` 指令直接定义了资源在缓存中的新鲜度。在有效期内, 缓存可以无需联系服务器就直接使用本地副本。
    -   例如：`Cache-Control: max-age=3600` 表示资源在 1 小时内是新鲜的。

. **强制验证：** `no-cache` 指令并不意味着不缓存, 而是强制缓存每次都向服务器进行验证。这意味着浏览器会发送带有 `If-None-Match` 或 `If-Modified-Since` 的请求。
    -   例如：`Cache-Control: no-cache` 配合 `ETag` 或 `Last-Modified` 使用, 可以确保获取到最新的资源, 同时又利用了带宽优化。

. **禁止存储：** `no-store` 指令是最严格的, 它完全禁止任何缓存存储响应。这通常用于包含敏感信息的资源。

. **公共/私有缓存：** `public` 和 `private` 指令控制了资源是否可以被共享缓存存储。`private` 确保了用户敏感数据不会被其他用户访问。

. **强制重新验证：** `must-revalidate` 确保了即使缓存过期, 也必须在与源服务器验证后才能使用。这在要求资源高度新鲜的场景中很重要。

=== 使用场景

-   **静态资源（CSS, JS, 图片）：** 通常设置较长的 `max-age`, 配合 `immutable` 指令, 并利用文件名哈希（如 `main.12345.css`）实现版本控制, 以达到最佳缓存效果。
-   **动态但变化不频繁的内容：** 可以设置一个短期的 `max-age`, 例如几分钟到几小时, 配合 `no-cache` 和 `ETag` 进行验证。
-   **API 响应：** 根据数据的敏感性和更新频率, 可以选择 `no-cache` 进行验证, 或者设置短期的 `max-age`。敏感数据可能需要 `private` 或 `no-store`。
-   **安全敏感信息：** `no-store` 或 `private, no-cache, no-store`, 确保数据不被任何缓存存储。
-   **用户个性化内容：** `private, no-cache`, 确保内容只对当前用户可见, 并且每次都需要验证新鲜度。

== 协同工作

* Etag 和 Cache-Control 并不是相互替代的关系, 而是互补的。它们通常会结合使用以达到最佳的缓存效果
* 当 `Cache-Control: no-cache` 时, 浏览器在读取缓存前, 如果资源有 Etag, 会发送 `If-None-Match`
* 如果资源有 `Last-Modified`, 会发送 `If-Modified-Since`
* 服务器通过比对 Etag (或 `Last-Modified`) 来判断资源是否发生变化, 并返回 `304 Not Modified` 或 `200 OK`

== 缓存失效案例

* 问题现象
+
在一次使用FireFox浏览器时, 发现本地测试没有问题, 发布到线上后出现问题, 但是用其它浏览器却也没有问题
* 原因
+
Firefox 磁盘缓存总容量和单文件大小有限制, 导致大文件不能被缓存, 本地没有这个限制
* 解决办法
+
.. 打开 `about:config`
.. 修改 `browser.cache.disk.max_entry_size` 调整总磁盘缓存大小
.. 修改 `browser.cache.disk.max_entry_size` 调整单个文件缓存大小
.. 注意 `browser.cache.disk.smart_size.enabled = false`, 否则前面两项设置无效
